# EXP-004 — Blog Post Inline-Simulator CTA Placement

- **Started:** 2026-05-08
- **Page:** `/blog/the-physics-of-a-perfect-launch`
- **Element under test:** simulator-CTA placement within the post body
- **Status:** live
- **Flag:** `?variant=B` (default A)
- **Min sample per arm:** 200
- **Variables held constant:** CTA copy, href, button styling, end-of-post CTA card (unchanged on both arms). Placement is the only variable.

## Hypothesis

Blog readers who reach the 2nd H2 of a long-form physics post are at a natural mid-scroll section break and have already invested ~3 minutes of reading attention. The current end-of-post CTA fires only after they finish — by which point they are mentally exiting. A pull-quote-style simulator CTA placed after the 2nd H2 should lift `simulator_runs / blog_post_visitor` without cannibalising the end-of-post CTA, because mid-scroll click-throughs come from a reader cohort that would otherwise have bounced before the article end.

## Mechanism

1. Long-form physics posts have a measurable mid-scroll attention dip — readers who started for SEO-driven curiosity decide somewhere between H2 #2 and H2 #3 whether to keep going or close the tab.
2. The end-of-post CTA reaches only the cohort that finished. The bounce-before-finish cohort never sees it.
3. An inline CTA placed at the section boundary catches part of the bounce cohort at the moment they are about to exit, while the cohort that *would* have finished still hits the unchanged end-of-post CTA on their natural exit.
4. Because the inline CTA copy and href are identical to the end-of-post card, this isolates placement from copy. If lift comes from B, the lift is attributable to the placement timing, not message framing.

## Implementation

- **page.js** — server component (preserves `export const metadata` for SEO + OG tags). Imports `InlineSimCta` and passes it as a prop to the existing `Prose` component, wrapped in a `<Suspense fallback={null}>` boundary.
- **InlineSimCta.js** — new client component. Reads `useSearchParams().get('variant')`. Renders a hidden placeholder span on variant A; renders a full pull-quote CTA card on variant B.
- **Prose component** — gained an `inlineCta` prop. A counter (`h2Seen`) increments on every H2 block; the CTA slot is injected directly after the 2nd H2 element so the slot lives at a natural section boundary. Variant A's hidden placeholder means the DOM tree shape is identical for both arms apart from the CTA block itself — no layout shift on control.
- **Analytics attribution** — `data-exp="EXP-004"` and `data-variant="A"` / `"B"` attributes on both the wrapper div and the Link element so client-side analytics can attribute clicks and views per arm without a separate flag-state read.
- **SEO posture** — same canonical URL, same `<h1>`, same metadata, same OG tags. Default = A so search-engine crawlers and shared links continue to see the unchanged content.

## Success criteria

- Ship variant B as the new control if **all** of:
  1. `simulator_runs / blog_post_visitor` lifts ≥15% over variant A
  2. p < 0.05 (two-proportion z-test)
  3. ≥200 samples per arm (no early-stop)
  4. End-of-post CTA absolute CTR does not drop >25% (additive test, not redistribution)
- If B wins, roll the same pattern out to the other 7 blog posts one at a time. Each replication is its own validation — do not assume a winner generalises across post topics blindly.

## Rollback criteria

Roll back to A (delete the inline-CTA block from the Prose injection) if any of:

- `scroll_depth_pct` drops >10% (inline CTA causing premature exits — readers see the CTA, click out, and the post never gets read past H2 #2)
- `post_dwell_time_s` drops >15% (CTA disrupting reading flow — net negative for content-quality signals like Search Console "useful content" ranking)
- End-of-post CTA absolute CTR drops >25% (full cannibalisation — we are moving the same clicks earlier rather than capturing new ones, which is a wash for the metric but a regression for content engagement signals)
- Bounce rate (single-page session %) increases >10%

## Sample-size logic

Min sample 200 / arm matches EXP-001/002/003. With current `/blog/the-physics-of-a-perfect-launch` traffic estimated at ~30 visitors/day, expected fill time is ~14 days per arm (~28 days total). If real traffic is meaningfully different, the postflight scheduler should flag a re-estimate after the first 7 days.
