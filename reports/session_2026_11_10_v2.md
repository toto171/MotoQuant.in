# MotoQuant 2.0 — open source, plain-language site, full audit

Session of 9–10 November 2026, branch `claude/jolly-gauss-febxxn`, PR #127.
One orchestrating session with cheaper worker lanes under strict file
ownership; every lane's work was re-checked before it was committed.

## What was asked

1. Audit the whole codebase and fix what hurts accuracy or efficiency.
2. Remove everything related to payments, including from the website.
3. Add an MIT licence.
4. Make the site easy for a first-time visitor while keeping every feature.
5. Do the long-postponed design overhaul.
6. Later: drop the "Pro" name; call the release 2.0.

## What shipped

### Open source
- `LICENSE` (MIT), `SECURITY.md`, `CODE_OF_CONDUCT.md`, rewritten README and
  CONTRIBUTING, `docs/adr/0006-open-source-mit.md`.
- "MotoQuant Pro" is now "MotoQuant" everywhere live. One version number,
  2.0.0, read from `motoquant.__version__`. `pip install -e .` works.

### Payments removed
- Website: pricing and refunds pages, tier badges, upgrade prompts, checkout
  calls. `/pricing` and `/refunds` redirect to the home page.
- Backend: `payments.py`, `subscriptions.py`, `usage.py`,
  `database/subscriptions_repo.py`, tier gates, licence keys, sim quotas and
  their tests.
- Database: `scripts/patch_2026_11_09_remove_billing.py` drops the
  `subscriptions`, `license_keys`, `payment_events` and `sim_usage` tables and
  the tier / payment-customer columns on `users`.
- Accounts remain, optional, only to save runs. Per-IP rate limits remain as
  abuse protection.

### Site: design system v6 and plain language (`web/DESIGN.md`)
- Light and dark themes; one vocabulary ("quarter-mile time", "Upgrades",
  "Race-day setup"); a glossary with in-place explanations of every term.
- Landing page is a server component built around a ten-second calculator.
- Simulator has a Simple mode (bike, rider, place) and an Advanced mode with
  everything that existed before. Upgrades and Race-day setup are step-by-step.
- Every result says which conditions it was computed for.
- Fonts are stored in the repository (`web/app/fonts/`), so the build needs no
  network. The Google Fonts fetch had failed CI twice.

### Audit fixes (accuracy and efficiency)
Physics and calibration
- Hot- and cold-day power correction follows the standard dyno formula,
  anchored so the reference day is bit-identical. Measured effect on a
  35–42 °C day: 10–30 ms.
- Dragy and ECU-log imports timed a run from the wrong instant when the log
  did not start from a stop; ECU speed columns are now unit-aware.
- The auto-calibrator's full preset fitted a parameter the engine does not
  read; bad parameter paths now raise instead of being ignored.

Advice tools
- The upgrade tool verifies its chosen build with real simulations and never
  recommends a part it has not simulated; parts with no straight-line effect
  are labelled as such.
- The race-day tool reports launch RPM as "not adjustable" when the bike's
  launch is not RPM-sensitive, instead of inventing a number.
- The plain-English parser no longer reads a model number or a year as a
  budget; when it cannot tell, it says so.

API and efficiency
- Catalog responses are cached as bytes and invalidated by a database
  change token; the simulator fetches the parts catalog once.
- Background job results are stored compressed under a memory budget.
- A stock-run cache removes the second simulation from part comparisons.
- Conditions (venue, altitude, temperature, humidity, pressure) are accepted
  by every simulation, upgrade and setup route and echoed in every result.
- Sign-in tokens are no longer echoed unless a development flag is set; the
  server no longer starts with a known default signing secret.

Catalog
- Headline specification columns that had silently inherited the GSX-R1000's
  values are now the bike's own or empty.
- 47 invented placeholder parts carrying real brand names are removed (9
  suspension, then 38 across air filters, brakes, bodywork, fuel systems,
  quickshifters and batteries). Three fabricated wheelie bars with made-up
  brand names are relabelled "Generic".
- Seven bikes that were the same motorcycle entered twice are merged; the
  sourced values (several kerb weights that had been entered as dry weights)
  were applied in the merge.

Catalog now: **534 bikes, 546 parts, 254 tyres, 1,765 tyre fitments, 20
venues.**

### A change that was measured and not shipped
The audit confirmed that 152 of 538 bikes had implausibly tall gearing, 117 of
them because small bikes fell back to a litre-bike primary ratio. A corrected
rule was built and measured. It made accuracy worse (weighted error 0.2629 →
0.2722 s; high-confidence bikes under 400 cc got worse) and no physically
plausible retune recovered it, so it was reverted. Details and evidence:
`reports/session_2026_11_10_epoch.md`. A plausibility check with a committed
baseline (`scripts/check_gearing_plausibility.py`, now 148 of 531 flagged)
stops the list growing. The site now says plainly that small bikes are the
weakest class.

## How the work was checked

- Audit by parallel readers, every finding independently verified before any
  fix was written.
- An adversarial review of the whole change: 35 findings, 33 confirmed and
  fixed, 2 refuted.
- A second review of the final cleanup: 23 findings, 18 confirmed and fixed.
  It caught seven tests the cleanup had broken and a test that could not fail.
- Three times a worker's report was wrong or its work failed spot-checks (a
  claim that the regression snapshot was unaffected; two parser versions that
  still mistook model numbers for budgets). Each was sent back or corrected.
- `scripts/audit_headline_stats.py` now also audits accuracy figures against
  the newest sweep report, and flags any of its own patterns that match
  nothing.

Final gates on the pushed tree: see the PR description for the full-suite
result, lint, baselines, site build and audits.

## Open items for the maintainer

1. **Set `JWT_SECRET` on Render.** Without it the server now generates a
   random secret per start, so sign-ins do not survive a restart.
2. **Scan the full git history for secrets before making the repository
   public** (for example with gitleaks). This session worked on a shallow
   clone and could only scan the current tree.
3. **Internal material still in the repository**: `outreach/`,
   `DISPATCH_*.md`, `data/growth_experiments.json`, `desktop/` and
   `.github/workflows/release.yml` (retired desktop app). Decide what to
   delete or move before going public; none of it was touched.
4. **Default conditions.** Catalog bikes simulate at Aamby Valley (679 m,
   22 °C, 40 % humidity) by default; the three reference presets at sea
   level. Every result now states its conditions, but one default would be
   simpler.
5. **Gearing for small bikes** needs sourced primary ratios, not an inferred
   rule.
6. **24 bikes** have bore and stroke figures that contradict their stated
   displacement; those columns are now empty pending a sourced correction
   (ids 34, 65, 69, 80, 87, 88, 94, 123, 290, 294, 297, 298, 300, 301, 302,
   304, 305, 311, 313, 320, 321, 696, 700, 3601). Ten bikes have no tyre
   fitment.
7. **Older catalog debt**: the July parts scrape marks roughly 146 remaining
   parts as "not found" at the listed retailer. They are real brands with
   plausible products, so they were kept, but they deserve a sourced pass.
8. Saved-run pages (`/r/[id]`) do not store the conditions of the run.
9. The instant-estimate model v2.7 has a slightly lower mean error than v2.6
   but a higher worst-case spread (RMSE 211 ms against 175 ms).
